Detecting overlap in CSS

Every CSS rule from Ahmad Shadeed's article on detecting overlap with CSS, explained, each with its own working example.

The article hides a decorative image once it runs into a section, without media queries or JavaScript. CSS has no "do these overlap?" check, so the article links several features into a chain. The only JavaScript on this page copies slider values into CSS custom properties and prints the code blocks. All detection is done in CSS.

How the pieces fit

  1. Anchor positioning: an invisible .measure box stretches across the gap between .decor and .section (§1–2).
  2. Gap < 20px: .measure's 20px-wide child no longer fits, so .measure becomes scrollable (§3).
  3. Scrollable: .measure's scroll-timeline switches from inactive to active (§4).
  4. Active timeline: an animation sets --touching: 1 on <body> (§5–8).
  5. --touching: 1: @container style(--touching: 1) hides .decor (§10–11).

1anchor-name

anchor-name gives an element a name, which must start with --. Absolutely positioned elements can then position themselves relative to it, wherever it sits in the DOM.

  • One element can have several names: anchor-name: --a, --b;.
  • The anchor must be laid out before the element that uses it. If the anchor is itself absolutely positioned, it has to come earlier in the DOM.
  • If several elements share a name, the last suitable one in DOM order wins (unless you limit it with anchor-scope). That's why every demo on this page uses its own names.

In the article

.decor   { anchor-name: --line; }
.section { anchor-name: --section; }

2position: absolute + the anchor() function

anchor(<name> <side>) only works in inset properties (top, right, bottom, left, inset-*) of an absolutely or fixed positioned element. Read it as "this edge of me goes to that edge of the anchor."

If you set both left and right and leave width as auto, the box stretches between them, so its width is exactly the gap. If the elements overlap, the width collapses to 0.

The browser handles the conversion for you. right: anchor(--section left) becomes "the distance from the containing block's right edge to the section's left edge."

Other side values are center, start, end, self-start, self-end and percentages (anchor(--a 25%)). You can add a fallback for when the anchor is missing: left: anchor(--a right, 0px). anchor() also works inside calc(), as in §1.

In the article

.measure {
  position: absolute;
  left:   anchor(--line right);     /* start where .decor ends */
  right:  anchor(--section left);   /* stop where .section starts */
  top:    anchor(--line top);       /* same vertical band as .decor */
  bottom: anchor(--line bottom);
}

3Making overflow the trigger: overflow-x: auto + ::after

  • overflow-x: auto makes the element a scroll container. Content wider than the box becomes scrollable instead of spilling out.
  • A fixed-width pseudo-element acts as a sensor. If the box is at least as wide as the sensor, nothing scrolls. If the box is narrower, or has collapsed to 0 because the elements overlap, the box overflows and becomes scrollable.
  • content: "" is required, or the pseudo-element isn't created. display: block lets width/height apply.
  • To change how close the elements can get before the image hides, change the sensor's width.
  • :after is the old CSS2 spelling; ::after is the modern one. Both work.

In the article

.measure { overflow-x: auto; }

.measure:after {
  content: "";
  display: block;
  width: 20px;                  /* the threshold */
  height: 100%;
  background-color: deeppink;   /* only so you can see it in the demo */
}

Example: a 150px sensor inside a resizable box

Go below 150px: the pink sensor gets clipped and a scrollbar appears. That's the overflow the technique detects.

4scroll-timeline

scroll-timeline turns a scroll container into a named timeline. Its progress runs from 0% to 100% as you scroll from start to end. It's shorthand for scroll-timeline-name and scroll-timeline-axis.

  • Axis values: block (default), inline, x, y.
  • The article needs x because .measure only overflows horizontally. With the default block axis, there's no vertical overflow, so nothing would ever trigger.

The technique depends on one rule: if the element has no scrollable overflow on that axis, the timeline is inactive, and animations attached to it don't apply.

So "is the timeline active?" means the same as "does this element overflow?" Nobody has to scroll.

In the article

.section-item-left { scroll-timeline: --box; }      /* axis defaults to block (vertical) */
.measure           { scroll-timeline: --touch x; }  /* horizontal axis */

5animation + animation-timeline

animation-timeline replaces the normal clock with a timeline. Here, that's a named scroll timeline. Two things to know:

  • Order matters. The animation shorthand resets animation-timeline to auto, so write animation-timeline after it. The article does this correctly.
  • Why 1ms? The article doesn't explain it. With a scroll timeline, a duration isn't real time. It's turned into a share of the scroll range, so a single animation fills the whole range whatever number you write. 1ms just has to be non-zero: an explicit 0s gives the animation no length, so it can't follow the scroll (box C below). Newer specs let you write auto for the same effect, but a small fixed duration is the widely compatible habit.
  • linear only matters for animations that should track the scroll, like the bars below.

In the article

.section-item-right {
  animation: reveal 1ms linear;
  animation-timeline: --box;
}

6@keyframes with from, to: an animation used as an on/off switch

  • from, to means 0%, 100%. With identical values at both ends, the value is the same at every point on the timeline. Scroll position doesn't matter, only whether the animation is running.
    • Timeline active (overflowing): the animation applies, so the property is 1.
    • Timeline inactive (not overflowing): the animation doesn't apply, the normal declaration wins, so it's 0.
  • Keyframes can set custom properties without @property. Unregistered properties change abruptly at the halfway point, which doesn't matter here because both ends are equal.
  • For contrast, the demo also has a second animation with different ends. It's registered with @property as an integer so it can interpolate, and it tracks the scroll position.

In the article

@keyframes flip-touch {
  from, to { --touching: 1; }
}

Example: switch vs. progress on the same timeline

7timeline-scope

By default, a named scroll timeline is only visible to the element that declares it and that element's descendants. Siblings and ancestors can't see it. Setting timeline-scope on a shared ancestor makes the name available to everything inside that ancestor.

The final technique uses this to move the switch up to the top of the page. The timeline is defined deep inside, on .measure, but the animation runs on <body>. So --touching is set on <body> and every element inherits it, including .decor.

In the article

/* sibling access */
.section { timeline-scope: --box; }

/* the final technique: hoisted all the way up */
body {
  --touching: 0;
  timeline-scope: --touch;            /* defined deep inside, on .measure */
  animation: flip-touch 1ms linear;   /* but runs on body itself */
  animation-timeline: --touch;
}

A Chrome quirk I found while testing (Chrome 157): when an animation reaches its timeline through timeline-scope, it stops applying at the very end of the scroll range. Scroll the left box below all the way down and the square drops back to grey.

This doesn't affect the technique, because nobody scrolls .measure. Animating the scroller itself, or one of its descendants, doesn't have this problem (§4 and §6).

8Custom properties + var()

  • A custom property declared on a parent is inherited by every descendant.
  • An animation can override it on a single element, because animation values beat normal declarations in the cascade.
  • var(--x, fallback) lets you supply a default value.

This example is the article's own side demo: .box-right is grey, and it turns pink while .box-left overflows.

In the article

.section   { --bg-color: lightgrey; timeline-scope: --bg; }
.box-left  { scroll-timeline: --bg; }
.box-right {
  background-color: var(--bg-color);
  animation: change-bg 1ms linear;
  animation-timeline: --bg;
}

9Relative color syntax: hsl(from …) + calc()

from <color> splits a color into channels (h, s, l in HSL) that you can reuse or adjust. Deeppink is about hsl(328 100% 54%), so hsl(from deeppink h s calc(l + 30)) keeps the hue and saturation and gives 84% lightness, a light pink.

The channel names stand for plain numbers, so you write calc(l + 30), not 30%. You can also convert between color spaces: rgb(from …) gives you r g b, and oklch(from …) gives you l c h.

In the article

hsl(from deeppink h s calc(l + 30))

10CSS nesting + @container style()

This rule combines two features:

  • Nesting: an at-rule placed inside a style rule. Declarations inside it apply to the outer selector. .decor { @container style(--touching: 1) { opacity: 0; } } is the same as @container style(--touching: 1) { .decor { opacity: 0; } }.
  • Style container query:
    • It checks the computed value of a custom property on an ancestor, instead of the ancestor's size.
    • Unlike size queries, it needs no container-type, because every element is a style container by default.
    • It checks the nearest ancestor (the parent, here), never the element itself. That works because --touching is inherited from <body>.
    • It works only with custom properties. Queries like style(display: flex) aren't supported.
    • You can combine conditions: style(--a: 1) and style(--b: 2).

In the article

.decor {
  @container style(--touching: 1) {
    opacity: 0;
  }
}

11opacity: 0 rather than display: none

The article hides the image with opacity: 0, which keeps its box. This matters because .decor is also the --line anchor that .measure is stretched from. With display: none, the box disappears, and the anchor goes with it. That creates a loop:

  1. The plate is hidden, so its anchor is gone and .measure can no longer span the gap.
  2. .measure shrinks to its 20px content and stops overflowing, so the switch goes back to 0.
  3. The plate comes back, .measure overflows again, and the plate is hidden again…

Chrome breaks the loop by settling on one state. In my tests (Chrome 157) that was sometimes "hidden" and sometimes "visible while overlapping", depending on timing. Either way, the result no longer reflects the layout.

opacity: 0 and visibility: hidden both keep the box and the anchor in place, so the measurement stays stable.

The demo runs the same chain twice, side by side. The only difference is how the plate is hidden. Both stages reuse the same anchor and timeline names: anchor-scope: all and timeline-scope keep each stage's names to itself.

Example: the full chain, hidden two ways

Drag the slider toward the plates a few times. The top plate hides every time the gap drops under 20px. The bottom one is unpredictable: it may stay visible while overlapping, or vanish and take the measurement with it. Its readout shows which state Chrome settled on.

Putting it all together

This is the article's technique, with the article's names (--line, --section, --touch, --touching). The only change: the article puts the switch on <body>, and this demo puts it on its own stage element so it doesn't affect the rest of the page.

The plate is 160px wide and the section starts at 30% of the stage width, so the plate hides once the stage is narrower than 600px (0.3 × 600 − 160 = 20px gap).

Browser support and caveats

  • The technique needs anchor positioning, scroll-driven animations (including timeline-scope) and style queries, all at once. The badges at the top test each one in your browser.
  • The author calls it a progressive enhancement. If a feature is missing, the image just stays visible. You could make that explicit with @supports (anchor-name: --a) and (animation-timeline: --a) { … }.
  • The threshold is a fixed width (20px in the article). Change the sensor's width to change it.
  • Hide the decorative element with opacity or visibility, never display: none (§11).
  • Two Chrome behaviors I found while testing this page (Chrome 157):
    • An animation that reaches its timeline through timeline-scope stops applying at the exact end of the scroll range (§7).
    • If timeline-scope is removed at runtime, the animation freezes, and it doesn't relink when the scope is added back.
    Neither affects the technique as written: .measure is never scrolled and the scope never changes. The pointer-events: none polish also stops anyone from scrolling .measure by accident.
  • The article credits the overflow-detection idea to Bramus Van Damme's work on detecting whether an element can scroll.
